    Prepare a configuration, step by step.
    Your profile keys stay in this browser tab. Nothing is uploaded or applied. Downloads contain secrets: keep them private.
    Before you begin: what do I need?
    1. A separate Linux server with Docker, plus VPN gateways that already reach your office.
    2. For each WireGuard road: a complete client .conf file from your network administrator. For IPsec: the gateway address, identities and shared secret.
    3. Your office network and Docker application network, plus office computers that reliably answer ping. Ask your administrator if these addresses are unknown.
    Two WireGuard roads? Click Add WireGuard profile twice. Only IPsec? Add IPsec settings for each road. You can mix them in any order.
    1. Where are you going?
    Office network means the range of private computers you want to reach. Docker application network means the range used by containers that need this VPN. They must be different and must not overlap the tunnel addresses. Check computers must belong to the office network and allow ping. Use your actual network addresses. Your gateway must already reach this network. The exported setup keeps public internet and SSH on the existing default route.
    2. Add roads in preferred order
    First road = first choice. Use the arrows to change priority. One to four roads are supported.
    3. Check, review and download
    Add your settings to begin.
    The package does not configure gateways or start the VPN. Extract into a private directory, set credentials to mode 0600, run doctor.py and follow QUICKSTART.md. Inbound application publication is off by default.
    

    Private configuration drafts
    First prepare and review profiles above. Saving sends their credentials to this server's private draft storage. It does not change active tunnels. Drafts are visible only to administrators; summaries hide keys.
    Archiving preserves the private copy and changes no tunnels. Eight active drafts and twenty-four archived copies are retained.
    

    Review and change your connection
    Choose a saved draft, then prepare it for the engine. Preparation and review keep the current connection running. Live changes are disabled by default; the controls below are for isolated acceptance testing until the complete installation passes its release checks.
    Archiving is reversible and changes no traffic. Selected, running and recovery-referenced settings are protected. Enter your current passphrase for archive or restore.

    Engine and switching status
    Loading engine status…
    Apply may briefly interrupt the VPN. After checking your real application, re-enter your administrator passphrase and confirm within three minutes. The passphrase is cleared after each sensitive action. If you cannot confirm, the engine requests a return to the previous settings. Recovery is complete only after fresh tunnel and application checks pass.
    Temporary preference or maintenance
    Prefer a healthy road or exclude one from selection while maintenance is in progress. Exclusion keeps health checks running. Healthy fallback and recovery thresholds still apply. These requests expire automatically and are cleared before a configuration change. After expiry, the preferred road returns once its normal recovery stability checks pass.
    Enter your administrator passphrase above for each request.
