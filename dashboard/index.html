    Prepare a configuration, step by step.

    Your profile keys stay in this browser tab. Nothing is uploaded or applied. Downloads contain secrets: keep them private.

    Before you begin: what do I need?
    1. A separate Linux server with Docker, plus VPN gateways that already reach your office.
    2. For each WireGuard road: a complete client .conf file from your network administrator. For IPsec: the gateway address, identities and shared secret.
    3. Your office network and Docker application network, plus office computers that reliably answer ping. Ask your administrator if these addresses are unknown.

    Two WireGuard roads? Click Add WireGuard profile twice. Only IPsec? Add IPsec settings for each road. You can mix them in any order.

    1. Where are you going?

    Office network means the range of private computers you want to reach. Docker application network means the range used by containers that need this VPN. They must be different and must not overlap the tunnel addresses. Check computers must belong to the office network and allow ping. Use your actual network addresses. Your gateway must already reach this network. The exported setup keeps public internet and SSH on the existing default route.

    2. Add roads in preferred order

    First road = first choice. Use the arrows to change priority. One to four roads are supported.

    3. Check, review and download

    Add your settings to begin.

    The package does not configure gateways or start the VPN. Extract into a private directory, set credentials to mode 0600, run doctor.py and follow QUICKSTART.md. Inbound application publication is off by default.
